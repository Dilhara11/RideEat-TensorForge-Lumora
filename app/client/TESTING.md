# Manual test walkthrough: the whole system, locally, through the UI

This runs the system the way it is deployed and submitted:
- **API:** the Docker image, started with the contract's `docker run` command plus `CORS_ORIGINS`.
- **UI:** a separate static app on its own origin, connected by CORS. On AWS it is hosted on Amplify; here `vite preview` plays that role.

Every expected result below was recorded with model `v1.2-558395869056`. Confidence values can differ by about
±1 % on other machines.

Test files are in `app/client/test-data/` (hand-written tickets, generated by `make-test-files.mjs`).

| File | What it tests |
|---|---|
| `01_quick_batch.csv` | 28 tickets in 6 languages, incl. a multi-line email. Has `expected_category` / `expected_urgent` columns to compare with the export |
| `02_with_errors.csv` | 7 rows, 5 invalid: bad channel, empty text, duplicate id, missing id, subject > 500 chars |
| `03_tickets.json` / `04_tickets.jsonl` | The same 5 tickets as JSON (`{"tickets": [...]}`) and JSONL |
| `05_large_job.csv` | 300 tickets → background job (finishes in ~15 s) |
| `06_no_header.csv` / `07_broken_quote.csv` | Unreadable files |
| `08_big_job.csv` | 2,000 tickets (~2 min), for cancel, queue-full and restart tests. Generated on demand |
| `09_too_many.csv` | 5,001 tickets, one over the job limit. Generated on demand |

## 0. Before you start

- **Docker:** Docker Desktop must be running, with WSL integration on for this distro. `docker ps` must work.
- **Free port 8000.** Stop any old container on it. An image built before the UI was separated still serves the UI at `/` and has no CORS:

  ```bash
  docker ps                       # any container on 0.0.0.0:8000?
  docker stop <container-id>      # e.g. the old tensorforge-api container
  ```
- **Browser address:** use **`http://localhost:4173`**, not `127.0.0.1`. The API allows exactly that origin.

## 1. Terminal 1: build and run the API container

```bash
cd ~/dev/TensorForge
docker build -f app/server/Dockerfile -t tensorforge-api .

docker run -d --name tf-api -p 8000:8000 \
  -e API_KEY=local-test-key \
  -e CORS_ORIGINS=http://localhost:4173 \
  tensorforge-api

docker logs -f tf-api           # watch the log; Ctrl + C only stops watching, not the container
```

- This is the contract command (`docker run -p 8000:8000 -e API_KEY=<key> <image>`) plus `CORS_ORIGINS`, so the browser UI is allowed in.
- `--name tf-api` without `--rm` keeps the container (and its job store) across `docker restart`, which the restart test in §6 needs.

✅ **Build:** the build log shows `import ok | model_version v1.2-558395869056` (the model hash check passed).

✅ **Run:** the log shows `Uvicorn running on http://0.0.0.0:8000`, then `model ready: version=v1.2-558395869056`.

✅ **Checks** in another terminal:

```bash
curl -s localhost:8000/health   # {"status":"ok","model_version":"v1.2-558395869056","model_loaded":true}
curl -s localhost:8000/         # JSON service card, not HTML (the API never serves the UI)
docker ps                       # tf-api ... Up ... (healthy)  (after ~15 s)
```

### Restart mid-job (contract: an interrupted job must fail, never vanish)

| # | Do | ✅ Expect |
|---|---|---|
| 6.10 | With an `08_big_job.csv` job **Running**, run `docker restart tf-api` | The container stops gracefully and starts again (~1 s, plus ~5 s model load). The UI may briefly show "Model loading…" or "Server unreachable" |
| 6.11 | Wait a few seconds | Banner gone, "Model ready". The job card turns **Failed**: "The server restarted while this job was running. Upload the file again to rerun it." (`error.code = interrupted`). Check: `docker logs tf-api` shows the shutdown and a new "model ready" |
| 6.12 | (optional) `docker stop tf-api`, wait ~30 s, then `docker start tf-api` | While stopped: the pill says **Server unreachable** and the red banner says "Can't reach the classification API at http://localhost:8000…". After start, it recovers by itself |

> Why `docker restart` and not `docker rm` + `docker run`: a new container starts with an empty job store, so the
> job would answer 404 instead of `interrupted`. In hosting, mount a volume (`-v tf-jobs:/app/data`) so a
> replaced container keeps its jobs.

## 10. API contract check (no UI)

With the `tf-api` container running (CORS on or off). The script runs on your machine as a client, so it uses the
server's Python venv (it only needs `httpx` and `jsonschema`):

```bash
cd ~/dev/TensorForge/app/server && source .venv/bin/activate
API_KEY=local-test-key python scripts/smoke_test.py --base-url http://localhost:8000
```

✅ Ends with **`55/55 checks passed`**. It checks every endpoint, error code and JSON schema against the container.
Run the same command with `--base-url https://<your-hosted-API>` and your real key after deploying.

## 11. Clean up

- UI: **Ctrl + C** in Terminal 2.
- API: `docker rm -f tf-api`. This removes the container and its job store; the `tensorforge-api` image stays for next time.
- Old images: list them with `docker images tensorforge-api` and remove unused ones with `docker rmi <image-id>`.
- In the browser, the key is forgotten when the tab closes (unless you ticked "Remember on this device": use **Set API key → Forget key**).
